# OhmyAIMCM 的 Scientific Agentic OS 架构

OhmyAIMCM 研究如何通过系统架构提高模型完成科研任务的能力。当前实现面向 CUMCM，将科研信息处理、科学图形、论文排版和证据审查接入同一任务环境。项目希望模型把更多推理投入问题本身，同时让研究过程中的重要产物保有可追溯的来源、版本和适用范围。

本文区分已经提供的机制、依赖 Agent 执行的工作约定，以及后续需要验证的能力增益。这里的 OS 是宿主 Agent 上的任务组织与执行层；当前发行形式为 20 个 Skill 模块及其资源和脚本，任务调度与工具权限由宿主提供。

## 1. 科研信息图处理

科研材料包含多种关系：页面中哪些块属于同一公式或图注，论断由哪些结果支持，哪些假设限制结论，以及结果修改后哪些页面需要更新。系统用不同表示处理这些关系，保留各自的语义边界。

| 表示 | 处理对象 | 所在环节 |
| --- | --- | --- |
| `LayoutIR` 与 `SemanticGraph` | PDF 中的文字、几何、结构角色与内容关系 | 离线论文解析与版式研究；本发行目录提供研究说明和运行时产物 |
| 证据关系图 `cumcm-evidence/1` | 当前任务中的事实、假设、推导、计算、解释、文献、图形、正文与审查对象 | 运行时按需建立，脚本随发行版提供 |
| `FigureIR` | 图形中的分面、数据映射、尺度、标注、科学不变量与导出来源 | 科学图形的规划、渲染和检查 |

离线解析阶段由解析器测量坐标和字体，模型标注内容角色与关系。这种分工使语义判断能够利用已有几何，又保留测量值的来源。相关技术与来源口径见[蒸馏说明](distillation.md)。

运行时证据关系图关注研究成果如何依赖彼此。每个节点包含稳定标识、类型、内容摘要、适用范围，以及指向具体文件和位置的来源记录。`depends_on` 表示上游依赖；`qualifiers` 表示必须随结论一起读取的限制、反面证据或竞争解释。两类关系都参与版本传播，限制条件不会被当作正面支持。

图形、正文和审查同样可以登记为节点。因此，一项数值结果的变化可以沿已声明的关系传递到结果图、解释段落和摘要。已有脚本提供四种操作：

| 操作 | 已实现行为 |
| --- | --- |
| `capture` | 为已有产物绑定 SHA-256，写入新快照；拒绝覆盖快照或静默接受已声明文件的变化 |
| `check` | 检查已声明文件是否缺失或改变，并传播其依赖状态 |
| `select` | 返回指定目标的上游读取集合，包括相关限制和来源定位 |
| `impact` | 预览指定目标发生变化时，哪些已声明的下游对象需要关注 |

这些操作为长任务提供局部读取和修订定位能力。Agent 仍需阅读所指向的原始材料、登记新增的重要产物，并执行必要的重算和审查。脚本不会自动推断遗漏的依赖、证明公式或重写正文。对于简单局部编辑，已有任务记录即可；只有跨产物依赖或版本变化值得追踪时才需要建图。

实现入口：[evidence_map.py](../skills/OhmyAIMCM/scripts/evidence_map.py)；数据约定：[证据关系](../skills/OhmyAIMCM/references/evidence-relationships.md)。

## 2. 将科学图形作为推理与表达工具

科学图形的起点是需要理解的关系。统计曲线用于比较数值或不确定性，关系图用于展示依赖，三维物理场景用于解释物体、界面和空间方向。图形可以检验一个暂定解释，图中出现的矛盾应进入模型修订。

系统通过 `FigureRequest` 记录问题或论断、受众、最终尺寸、数据来源和单位；`DataProfile` 描述数据类型、缺失情况及变换；`FigureIR` 将这些信息展开为可检查的分面、编码、尺度、标注和导出计划。对于物理场景，数据说明对应几何来源、实体、坐标和未知尺寸。

图形设计将科学不变量与审美选择分开。数值标记由确定性代码生成，物理结构需要有模型或几何来源；模型可以选择布局、颜色和表达形式。复杂示意图可以采用经核对的 Blender 或 SVG 草图，再按需要引入图像模型细化，同时保留精确几何和科学标注的确定性图层。

检查覆盖表示结构、来源记录和实际最终尺寸下的可读性。导出文件需保留对应的代码或原生图源；图像模型生成的栅格层记录其生成来源和编辑范围。审美比较在科学含义和导出条件满足后进行。这个设计让模型能够尝试丰富的视觉表达，并明确哪些部分必须忠实于证据。

实现与约定：[图形主入口](../skills/OhmyAIMCM-scientific-figure-maker/SKILL.md)、[FigureIR](../skills/OhmyAIMCM-scientific-figure-maker/references/figure-ir.md)、[图形契约检查](../skills/OhmyAIMCM-scientific-figure-maker/scripts/validate_figure_contract.py)。

## 3. 将排版组织为保留内容的编译过程

排版系统以已经完成的正文为输入，沿 Markdown、Pandoc AST、Lua Filter、LaTeX 和 PDF 的路径生成可编辑产物。公式、图表、编号和交叉引用以其内容与关系为保留对象，版式选择通过有限的 `Style Tokens` 表达。

这种设计把论证修改与页面组成分配给不同职责。模型负责决定解释是否充分、图注是否准确；排版工具处理语义环境、自动编号、表格分页和页面检查。若排版暴露出图中文字过小或源表格设计问题，问题应返回相应内容或图形环节，修订后再生成当前版本。

系统输出内容锁、构建报告和布局审计，并保留图源及其哈希。自动检查可以发现其覆盖范围内的编译、缺图、内容一致性和溢出问题；实际页面仍需要视觉检查，科学论证由内容审查负责。检查记录分别说明检查维度和绑定版本，避免把一次编译成功当作整篇论文已经完成评审。

当前默认 `journal-dense-cn-v1` 是作者选择的旧版投影。后续版式研究尚无符合运行时导出条件的新共识因子。这种准入边界也是架构的一部分：研究中观察到的关联，经过相应检查或明确选择后才成为排版控制。

实现与约定：[排版主入口](../skills/OhmyAIMCM-typesetter/SKILL.md)、[样式策略](../skills/OhmyAIMCM-typesetter/references/aesthetic-policy.md)。

## 4. 按需上下文与条件化经验

主入口按当前操作选择最小必要模块。建模方法由实际对象、变量和约束决定，任务不预设固定算法菜单，也不要求每次都运行完整论文流程。模型可以交替建模、计算和解释；局部改稿直接进入写作。

论文蒸馏为这种组织方式提供可检索资源。写作技巧同时保留具体动作、适用条件和误用提醒，运行时只为当前表达困难查询相关规则。例如，“搜索覆盖与停止理由”要求说明搜索范围及停止依据，并将局部搜索支持的结论与全局最优性证明区分开。

离线资源准备和任务时检索分别进行。原始语料不在每次任务中整体加载，检索摘要也作为待核对资料使用。模型根据当前证据判断技巧是否适用；没有合适匹配时继续按材料组织论述。系统希望借此减少无关上下文和固定模板对探索的干扰，其实际收益仍需评测。

实现与约定：[协调入口](../skills/OhmyAIMCM/SKILL.md)、[技巧查询器](../skills/OhmyAIMCM-writing/scripts/query_variants.py)、[条件技巧数据](../skills/OhmyAIMCM-writing/references/technique-variants.json)。

## 5. 探索自由、成果约束与协作

模型在授权范围内保有假设、方法、实验和叙述选择。约束作用于研究成果的使用：什么可以作为计算结果，什么足以支持某种结论，哪些版本需要重新检查。失败的假设和未完成的实验可以保留为探索记录。

| 边界 | 机制 | 执行方式 |
| --- | --- | --- |
| 计算与呈现 | 保存全精度输出、单位、执行记录及数值诊断，再生成图表 | 运行记录脚本与 Agent 的数值检查共同承担 |
| 结果与论断 | 区分给定事实、临时假设、计算输出和解释，携带适用范围及不利证据 | 写作与科学审查约定，图结构提供版本辅助 |
| 图形与证据 | 数据映射、单位和科学不变量保持一致，检查最终尺寸 | 图形契约脚本与实际语义、视觉检查共同承担 |
| 内容与版面 | 定稿内容经受限转换进入排版，保留图源与内容锁 | 排版脚本与逐页检查共同承担 |
| 修订与旧审查 | 审查绑定具体产物版本，变更后回查受影响使用 | 版本辅助脚本定位，Agent 执行修复和复核 |

任务足够复杂且宿主允许时，可将有独立输入的工作交给原生 Agent。交接包含目的、产物路径和版本、已有证据、必要限制及写入边界；同一可变产物在同一时刻由一个作者写入。主代理负责整体答案，写作角色负责正文整合，审查者返回定位明确的缺陷。

协作的完成以实际返回的产物和检查结果为依据。修复之后需要读取整合稿，检查术语、段落衔接和摘要是否仍对应当前证据。独立科学审查与机械检查分别记录；独立审查不可用时明确保留该缺口。

上述约定依赖宿主 Agent 正确执行。脚本可以检查文件、结构和部分一致性，科研判断仍由模型与审查者承担。具体职责见[交接约定](../skills/OhmyAIMCM/references/handoffs.md)、[计算模块](../skills/OhmyAIMCM-compute/SKILL.md)和[审查模块](../skills/OhmyAIMCM-review/SKILL.md)。

## 6. 如何验证系统是否释放了更多模型能力

当前案例展示了这套组织方式可以产出的论文形态，局部回归检查了若干工具功能与结论措辞。作者的多轮实践观察支持继续开展该方向研究。要判断系统相对于不使用 Skill 的净收益，需要额外的同模型对照；本节是拟议评测设计，尚无对应的完整实验结果。

基线与系统组应使用相同模型版本、题目及附件、工具权限、计算与 token 预算，并记录人类介入。基线能够使用相同工具，但不加载本项目的指令和蒸馏资源。多个任务、重复运行与独立盲评用于检查效果是否稳定，并报告失败案例。

| 评价维度 | 可核查的结果 |
| --- | --- |
| 科学与数值正确性 | 按题目要求检查答案、推导、约束、数值收敛及结论适用范围 |
| 证据一致性 | 核查来源是否支持论断，以及修改结果后正文、图表和摘要是否遗漏更新 |
| 图形与排版 | 分别检查科学编码、最终尺寸可读性、内容保留和交付完整性 |
| 探索与效率 | 比较任务完成率、发现并纠正错误的情况、资源消耗和人工修复量 |

消融实验可分别移除证据关系图、条件技巧、图形契约或内容保真排版，在相同条件下观察对应变化。这样才能区分基础模型的能力、工具接入的作用与系统组织方式的贡献，也能识别哪些约束改善结果、哪些约束增加负担。

现有公开证据及其覆盖范围见[蒸馏验证说明](distillation.md#覆盖和验证分别怎么算)。
