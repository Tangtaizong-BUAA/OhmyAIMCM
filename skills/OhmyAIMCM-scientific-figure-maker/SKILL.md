# OhmyAIMCM-scientific-figure-maker

Create the smallest figure that helps explain, test or communicate the scientific relationship without inventing evidence. A plot may challenge a provisional claim; preserve data and scientific meaning before optimizing appearance.

## Required workflow

1. Lock the request.
   - Identify audience, target medium, final physical size, language, claim, data source, units, transformations, uncertainty meaning, and required editable format.
   - For exploratory requests, record the question being explored in the claim field. Pause a data-bearing render only when required data or scientific meaning is missing; resolve ordinary styling omissions from context.
   - Build a `FigureRequest` and `DataProfile`; read [references/figure-ir.md](references/figure-ir.md).
2. Apply integrity gates.
   - Reject fabricated values, deceptive axis limits, unsupported uncertainty, hidden missingness, silent sample removal, incorrect units, or encodings that imply false magnitude.
   - Read [references/selection-and-integrity.md](references/selection-and-integrity.md) for chart selection and hard constraints.
3. Select the rendering route.
   - Read [references/routing.md](references/routing.md) and invoke only the minimal downstream Skills needed.
   - Look up an existing library recipe before writing new plotting code: read [references/material-library.md](references/material-library.md). Bundled styles and RGB tables work without the research checkouts; specialized recipes resolve to locked source paths.
   - Quantitative/data-bearing marks must be generated by deterministic code.
   - For workflows and mechanisms, read [references/diagram-design.md](references/diagram-design.md). Its paper typography and visual defaults also apply to custom Matplotlib/TikZ/SVG code, not only FigureSpec or draw.io.
   - For physical setups where depth, bodies, interfaces or orientation explain the model, actively consider a scene and read [references/physical-scenes.md](references/physical-scenes.md). Use an actual 3D scene renderer when needed; a statistical plot or extruded flowchart is not a physical scene. Keep native geometry/source plus requested exports.
   - For complex illustrative mechanisms or physical scenes, actively consider a verified Blender/SVG draft followed by image-model refinement; it may form the main explanatory image, not just decoration. Read [references/image-assisted-figures.md](references/image-assisted-figures.md) only when this route is useful. Keep exact geometry, data marks, fields, scales, equations and scientific annotations in deterministic layers; recheck the generated structure against the model.
4. Plan before polishing.
   - Create a `FigureIR` with panels, encodings, scales, annotations, style tokens, export targets, and provenance.
   - Separate scientific invariants from aesthetic degrees of freedom.
   - Resolve typography as its own figure decision, not a manuscript-font inheritance.
     Read [references/figure-typography.md](references/figure-typography.md) for mixed
     CJK/Latin/math labels or a font complaint; inspect actual faces and final-size exports.
   - For comparisons, vary one decision axis at a time unless the task is explicitly a tradeoff study.
   - For statistical plots, resolve one style family with `scripts/figure_library.py`; explicit dimensions and style overrides take precedence over its dated presets. Use one layout owner and the shared `OhmyAIMCM-scientific-visualization/scripts/figure_export.py` exporter. Native vector/TeX tools use their own export with the same size/evidence checks.
   - Keep a main-text figure only if it adds a needed comparison, explanation or uncertainty statement. Do not accumulate chart types repeating one finding; retain useful supporting exploration in an appendix.
5. Render and validate.
   - Keep source code or native diagram source alongside SVG/PDF/PNG exports.
   - Run `python3 scripts/validate_figure_contract.py request.json ir.json`.
   - Run `python3 scripts/audit_svg.py output.svg` for every SVG; this checks structure and references, not visual overlap. Embedded PNG/JPEG layers are permitted with route-specific provenance and effective-resolution review; image-assisted illustrations additionally need the source/model comparison in their route guide.
   - Inspect the actual final-size render; check clipping, overlap, contrast, grayscale distinction, CJK glyphs, legend/label consistency, and panel order.
6. Rank only valid candidates.
   - First remove candidates that fail integrity or export gates.
   - Use human preference or a learned preference score only among admissible candidates.
   - Never interpret an aesthetic reward as scientific correctness.
7. Deliver an evidence bundle.
   - Include editable source, SVG/PDF, review PNG when requested, `FigureIR`, data/source hash, font and palette record, validation report, and unresolved limitations.

## Calibration mode

For owner-specific aesthetic calibration, use the local `figure-lab` platform documented in [references/calibration-contract.md](references/calibration-contract.md). It provides 150 controlled A/B tasks and 300 deterministic SVGs. DeepSeek V4 Flash is an optional text-only observation coach and must never select the winner.

## Output contract

Do not call a figure complete until all applicable gates pass:

- semantic: the visual faithfully communicates the supported claim or exploratory question, including contrary evidence;
- statistical: values, uncertainty, sample sizes, transforms, and missingness are truthful;
- perceptual: the encoding and ordering permit the intended comparison;
- geometric: no clipping, overlap, label intrusion, or illegible final-size text;
- accessible: color is not the only critical channel and contrast is adequate;
- reproducible: data, code, seeds when available, source hashes and exports are recorded; generated layers retain prompts, references and actual invocation evidence, without promising identical regeneration;
- editable: the user receives source appropriate to the route; a generated raster is not a recovered mesh or fully editable vector.
